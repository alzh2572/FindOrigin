# План реализации FindOrigin

Поэтапный порядок работ по реализации Telegram-бота согласно [PROJECT.md](./PROJECT.md).

---

## Этап 1. Инициализация проекта

1. Создать Next.js-приложение (App Router, TypeScript).
2. Настроить структуру каталогов:
   - `app/api/webhook/route.ts` — обработчик webhook Telegram
   - `lib/telegram/` — клиент Telegram API
   - `lib/parser/` — извлечение текста и сущностей
   - `lib/search/` — поиск источников
   - `lib/ai/` — сравнение смысла и ранжирование
   - `lib/types/` — общие типы
3. Добавить переменные окружения:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_WEBHOOK_SECRET` (опционально, для проверки запросов)
   - ключ API поиска (например, `SERPER_API_KEY` или аналог)
   - ключ AI-провайдера (например, `OPENAI_API_KEY`)
4. Обновить `.gitignore`, убедиться, что `.env` не попадает в репозиторий.

---

## Этап 2. Webhook и базовый ответ бота

1. Реализовать `POST /api/webhook`:
   - принять `update` от Telegram;
   - извлечь `chat.id` и `text` из `update.message`;
   - игнорировать сообщения без текста (стикеры, фото без подписи и т.п.).
2. Реализовать клиент Telegram API:
   - метод `sendMessage(chatId, text)`;
   - обработка ошибок и таймаутов.
3. Обеспечить быстрый ответ **200 OK**:
   - webhook не выполняет долгие операции синхронно;
   - тяжёлая обработка выносится в фоновую задачу (см. этап 3).
4. Добавить скрипт или route для регистрации webhook (`setWebhook`) на URL Vercel.
5. Локально протестировать: бот отвечает эхом или коротким «Принято, ищу источники…».

---

## Этап 3. Асинхронная обработка запросов

1. Разделить поток на две части:
   - **быстрый webhook** — валидация, постановка задачи, 200 OK;
   - **фоновая обработка** — поиск и AI-анализ.
2. Выбрать механизм фоновой обработки для Vercel:
   - `waitUntil` / Edge-функция, или
   - отдельный internal API route, вызываемый без ожидания результата.
3. Отправлять пользователю промежуточное сообщение («Обрабатываю…»), затем финальный результат.
4. Добавить базовую обработку ошибок: при сбое — понятное сообщение пользователю.

---

## Этап 4. Приём и нормализация входных данных

1. Определить типы входа:
   - произвольный текст;
   - ссылка на Telegram-пост (`t.me/...`).
2. Для текста — очистка и нормализация (лишние пробелы, переносы).
3. Для ссылки на Telegram-пост:
   - распознать формат URL;
   - извлечь текст поста (через публичный preview / парсинг, если пост доступен);
   - при недоступности — сообщить пользователю, что нужен текст напрямую.
4. Валидировать минимальную длину текста; при слишком коротком вводе — попросить уточнить.

---

## Этап 5. Извлечение ключевых сущностей

1. Реализовать модуль парсинга, который из текста выделяет:
   - ключевые утверждения;
   - даты;
   - числа;
   - имена (люди, организации);
   - ссылки.
2. Использовать AI для структурированного извлечения (JSON-схема на выходе).
3. Сформировать «поисковый профиль» запроса:
   - 2–5 поисковых фраз на основе утверждений и сущностей;
   - фильтры по датам, если они указаны.
4. Покрыть unit-тестами парсинг типовых сообщений (новость, пересказ, пост со ссылкой).

---

## Этап 6. Поиск возможных источников

1. Подключить поисковый API (web search).
2. Выполнить несколько запросов по «поисковому профилю».
3. Собрать кандидатов из категорий:
   - официальные сайты (gov, официальные пресс-релизы);
   - новостные сайты;
   - блоги;
   - исследования и научные публикации.
4. Отфильтровать дубликаты, агрегаторы и явный мусор.
5. Для каждого кандидата получить:
   - URL;
   - заголовок;
   - сниппет / краткое содержание (если API позволяет).
6. Оставить топ-N кандидатов (например, 10–15) для AI-оценки.

---

## Этап 7. AI-сравнение смысла и ранжирование

1. Передать в AI:
   - исходный текст пользователя;
   - структурированные сущности;
   - список кандидатов с заголовками и сниппетами.
2. Попросить модель оценить **семантическое совпадение**, а не дословное:
   - насколько источник подтверждает или опровергает утверждение;
   - является ли источник первичным или пересказом.
3. Получить от AI:
   - 1–3 лучших источника;
   - оценку уверенности для каждого (например, «высокая / средняя / низкая» или 0–100%);
   - краткое объяснение, почему источник релевантен.
4. При отсутствии надёжных совпадений — честно сообщить об этом.

---

## Этап 8. Формирование ответа пользователю

1. Сформировать читаемое сообщение в Telegram (Markdown или HTML):
   - краткий вывод;
   - список из 1–3 ссылок;
   - уровень уверенности по каждой;
   - пояснение в 1–2 предложения.
2. Ограничить длину сообщения лимитами Telegram (разбить на части при необходимости).
3. Добавить disclaimer: результат — вероятностная оценка, не юридическое заключение.

---

## Этап 9. Деплой на Vercel

1. Подключить репозиторий к Vercel.
2. Настроить переменные окружения в панели Vercel.
3. Задеплоить production-сборку.
4. Зарегистрировать webhook на production URL (`https://<domain>/api/webhook`).
5. Проверить end-to-end сценарий на production:
   - текст → ответ с источниками;
   - ссылка на пост → извлечение → ответ;
   - некорректный ввод → понятная ошибка.

---

## Этап 10. Наблюдаемость и доработки

1. Добавить логирование ключевых этапов (без персональных данных сверх необходимого).
2. Обработать rate limits внешних API (поиск, AI, Telegram).
3. Добавить таймауты и fallback при недоступности сервисов.
4. По результатам тестов уточнить промпты AI и правила фильтрации источников.
5. (Опционально) кэширование повторяющихся запросов; команда `/start` с инструкцией; поддержка нескольких языков.

---

## Порядок зависимостей между этапами

```
Этап 1 → Этап 2 → Этап 3 → Этап 4 → Этап 5 → Этап 6 → Этап 7 → Этап 8 → Этап 9 → Этап 10
```

Этапы 4–8 — основная бизнес-логика; их можно разрабатывать параллельно с заглушками, но интеграционное тестирование выполняется только после этапа 3.

---

## Критерии готовности MVP

- [ ] Бот принимает текст и отвечает в Telegram.
- [ ] Webhook возвращает 200 OK без блокировки долгими операциями.
- [ ] Из текста извлекаются ключевые сущности.
- [ ] Выполняется поиск и AI-ранжирование источников.
- [ ] Пользователь получает 1–3 ссылки с оценкой уверенности.
- [ ] Бот задеплоен на Vercel и работает через webhook.
